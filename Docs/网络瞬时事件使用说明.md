# 网络瞬时事件

瞬时事件描述服务器已经确认发生的一次动作。首期实现开火：每成功射出一发子弹生成一个 `FireEventMessage`；命中判定以后使用独立事件，不把开火等同于命中。

## 类型与传输

- `NetworkEventMessage : Mirror.NetworkMessage`：可继承的事件基类。
- `FireEventMessage : NetworkEventMessage`：一次成功开火。
- `NetworkEventEnvelope : Mirror.NetworkMessage`：实际交给 Mirror 收发的结构体，`payload` 保存事件对象。
- `NetworkEventSerialization`：使用稳定事件类型码和显式二进制字段编码，还原具体子类。

当前 Mirror 的顶层收发接口要求 `struct, NetworkMessage`，所以不要直接调用 `NetworkClient.Send(fire)` 或 `NetworkServer.SendToAll(fire)`。服务器统一通过 `NetBridge.BroadcastEvent(message)` 发送。客户端没有上传这类事件的入口，仍只提交输入。

所有事件共用可靠有序通道，只发送给 Ready 客户端，也包括射手本人。客户端按全局递增的 `eventId` 去重，断线关闭和重新初始化时重置记录。

## 开火数据

| 字段 | 含义 |
| --- | --- |
| `eventId` | 本次服务器运行期间全局递增的唯一事件编号，0 无效 |
| `serverTick` | 服务器确认开火的模拟拍 |
| `netId` | 射手的网络标识 |
| `predictionEpoch` / `inputTick` | 对应客户端输入的轮次与拍号 |
| `position` | 开火时服务器角色位置 |
| `origin` | 服务器视角节点的世界位置；未配置视角节点时回退到角色位置 |
| `direction` | 根据服务器模拟的 pitch/yaw 计算的单位方向 |

## 接收事件

在客户端运行时初始化后订阅 `ClientManager.EventReceived`，使用同一个 ClientManager 实例成对退订：

```csharp
void OnNetworkEvent(NetworkEventMessage message)
{
    if (message is not FireEventMessage fire)
        return;

    bool isLocal = NetworkClient.localPlayer != null &&
        fire.netId == NetworkClient.localPlayer.netId;

    // isLocal 时作为权威确认，不重播本地已经预测的枪声和动画。
    // 远端消费者可直接使用 fire.origin / fire.direction。
    // 不调用 Gun.TryFire()，不在接收回调里再次扣弹。
}

client.EventReceived += OnNetworkEvent;
// 消费者停止时：client.EventReceived -= OnNetworkEvent;
```

事件数据不要求射手对象已经生成；即使尚不能通过 netId 找到角色，回调仍正常交付。本次只提供消息与回调，没有新增远端声音、动画或特效。

## 输入与预测边界

`PlayerInputDriver.Consume()` 生成同一份 `PlayerInputFrame`，同时用于本地预测和输入上传。实时输入统一交给玩家门面：本地调用 `PlayerBrain.StepPredicted(frame)`，服务器调用 `PlayerBrain.StepServer(frame)`。门面内部按“运动模拟 → 动作与切栏 → 枪械步进”的顺序分发，只有枪械通过准备、冷却和弹药检查并成功扣弹，返回结果的 `Fired` 才为 `true`。

`PlayerLiveStepResult` 只携带本拍的运动状态 `State`、实际开火事实 `Fired` 和开火几何 `FireOrigin` / `FireDirection`，不包含网络事件号、连接或消息。射线起点和方向由玩家模块生成。`ServerManager` 负责解析输入队列，调用玩家门面，完成后确认该拍，再为开火事实补充 `eventId`、`serverTick`、`netId`、`predictionEpoch` / `inputTick` 并广播；快照与新预测基准也通过 `PlayerBrain.State` 读取状态。网络层不直接驱动运动、武器或视角组件。

运动结果交给 `PlayerMotionController` 消费，成功跳跃通过 `Motion.OnJumped` 通知，跳跃结果不经过武器控制器。本次没有新增跳跃网络消息。Editor 中服务器每次成功开火会沿广播消息的同一起点和方向绘制一条 100 米红色射线，保留 3 秒；绘制由 `UNITY_EDITOR` 保护。

缺失输入不会延续上一拍的开火意图；重复输入由输入队列去重。枪械使用独立时钟，移动重同步不重置它。移动回滚仍直接调用 `IPlayerSimulation` 恢复和重放运动，不调用 `StepPredicted` / `StepServer` 实时门面，因此不会重复切栏、扣弹、通知跳跃、播放声音或动画，也不会再次广播。当前没有武器状态快照与弹药回滚，运行时拾取装备同步也不属于这次事件层实现。

## 扩展新事件

1. 添加继承 `NetworkEventMessage` 的具体事件类。
2. 在 `NetworkEventKind` 分配未使用的固定编号，并扩展读写器的类型映射和字段编码；不要使用 `GetHashCode()` 作为线上类型码。
3. 在玩家模块中确认事件事实，通过实时门面结果交给 ServerManager 补充网络元数据并构造消息，使用同一个全局事件序号，再调用 `BroadcastEvent`。
4. 客户端订阅统一回调并按具体子类消费。未来命中事件可引用开火事件的 `eventId` 关联同一发子弹。

不要把同一事件流改发到乱序通道，也不要为各个子类分别从 1 计数；客户端去重依赖可靠有序传输和全局序号。当前协议版本为 3，不兼容版本 2 的开火语义。
